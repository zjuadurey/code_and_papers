# QThin regular-file materialization protocol

Frozen predecessor: df29e7c. No corpus expansion, simulator runtime or partition changes.

The native program appends one physical bit q. Existing physical bits retain their indices. Local coefficients are separate command-line metadata. CX(v,p), CX(p,v), CZ and a 4×4 unitary with local order [v,p] are implemented. The streaming target must fit inside a chunk; primary p=3, sensitivity p=18. Higher/inter-chunk bit shuffles and batch k>1 are outside this initial prototype.

Native buffers are four aligned chunks at most, at most 256 MiB. The same allocation and kernel family serves both policies. Input state files are index-deterministic complex128 values, generated and fdatasynced before measurement. All native output opens require a new regular file (O_EXCL, O_NOFOLLOW); no raw-device write, cache-dropping command, mount, discard or TRIM command exists.

Primary product experiments compare naive explicit expansion (read B, write 2B, sync; read 2B, write 2B, sync) with fused post-gate emission (read B, write 2B, sync). The naive gate pass updates the output file in-place after reading both affected branch chunks. The sparse BASIS baseline writes only the active branch after ftruncate, then reads and writes the full output in the gate pass. Its expected application traffic is 6B; explicit BASIS is 7B; fused is 3B. Sparse holes are not assumed to cost zero at every lower accounting level.

The timed/counter interval begins immediately before ftruncate and ends after final fdatasync. Initial file open/create, buffer allocation/initialization, input-generation, input fadvise, post-run sample validation, CSV logging and cleanup are outside the interval. Intermediate baseline fdatasync and DONTNEED are inside. operation_elapsed excludes time within fdatasync calls; total includes both phases and synchronization. These are completion measurements, not a power-loss durability guarantee.

Process I/O snapshots and mapped device counters are sampled independently. Shared device counters include unrelated guest processes and filesystem effects; WSL counters do not measure host-controller/NAND traffic. O_DIRECT avoids the guest page cache, not necessarily Windows/host/device caches. fdatasync completion does not prove all bytes reached NAND. Host VHDX volume free space is included in conservative capacity planning; this can skip a case that might reuse already allocated virtual-disk extents, in favor of preventing host ENOSPC. No host physical-device identity is inferred from the guest 'Virtual Disk' model.

The full planned matrix and execution order are saved before running. Sizes use 5 repetitions through q=28 and 3 at q>=29. Gate/state group order and policy order within repetitions are seeded and randomized. One generated input is retained per size, every output is removed after its counters and sample results have been durably journaled, then the input is removed. Extra chunk, buffered and higher-bit experiments use 3 repetitions. Main 16 MiB DIRECT rows are reused as sensitivity baselines, avoiding duplicate matrix entries.

The supplied |+> target of CX(p,v) is an X eigenvector and remains factorized. It is deliberately kept as a forced-materialization/control case, but excluded from the mechanism's preregistered decision aggregate. Main large decision set is q>=28, primary DIRECT if supported (otherwise explicitly BUFFERED), all other product states/gates. If no q>=28 completes, q>=26 is reported as a smaller fallback with its limitation. Per-configuration ratios use medians of repetitions; overall decision statistics are medians of those ratios. CV is sample standard deviation divided by mean. No trial is discarded as a timing outlier.

STRONG requires >=2× algorithmic and available measured-counter traffic reduction and >=1.5× latency reduction on the decision set, correctness clean. PROMISING requires >=1.5× measured traffic and >=1.2× latency or strong traffic with runtime masked by storage/kernel effects; unstable or <=1.2× timing is MIXED and investigated. WEAK requires valid measurements that erase both traffic and runtime benefit. Missing lower-level counters remain NA; application counters alone are not physical SSD evidence. Whole-trace 5.243× is not the target for this one-event experiment.
