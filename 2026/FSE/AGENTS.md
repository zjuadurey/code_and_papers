# FSE 工作区入口

本目录的研究项目在 [qrefactorbench/](qrefactorbench/)，目标为 FSE 2027。
当前论文编辑目录是 [paper/](paper/)，主文件 [main.tex](paper/main.tex)。
该目录由用户指定的论文目录重命名而来；不要改回旧名或继续编辑历史草稿副本。
不要把本目录当成空仓库，也不要在这里重新初始化项目。

新对话开始工作前，自动按以下阅读链恢复上下文；这是 Agent 的职责，
不要求用户提供文件路径、粘贴交接提示或重述研究 idea。
用户只需直接说任务，或说 **“继续”**。用户说 **“读取当前目录”** 时只读恢复并汇报。

阅读链：

1. [项目 AGENTS.md](qrefactorbench/AGENTS.md)
2. [研究意图](qrefactorbench/docs/RESEARCH_CHARTER.md)
3. [当前状态](qrefactorbench/PROJECT_STATUS.md)
4. [下一步](qrefactorbench/NEXT_ACTIONS.md)
5. [论文交接](paper/HANDOFF.md)；论文任务再读 [paper/AGENTS.md](paper/AGENTS.md)。

随后按项目入口规定简短汇报：研究目标、当前阶段、已有证据、当前版本、下一步。
这是只读恢复上下文的请求，不自动修改文件、跑测试或启动模型/真机实验。
用户说“继续”时才按项目队列推进已授权的安全工作。
无需用户重新解释研究 idea；不要用历史日志取代当前状态，也不要覆盖未提交内容。
研究状态以 PROJECT_STATUS 为准，论文编辑位置以 paper/ 为准；旧草稿和 latex.zip 是交付快照，
不会自动同步。论文中的拟议方法和实验不代表代码已经实现，也不授权新实验。

## 并行推进：用户不负责记分工或管理目录

- 用户始终可以在原 FSE 目录开始对话，无需记 ABC、三个任务、worktree 路径或启动命令。
- 新对话尚未确定负责范围时，用户只说“继续”也足够：Agent 读完文档后主动列出当前可推进的
  任务（编号、每项一句话）并给出推荐项；用户只需选编号或说“就推荐的”。
  不反问“你要做什么”，不要求用户先报任务名或先问分工。这条优先于直接执行总队列的默认规则。
- 用户问“现在怎么推进”、忘了分工或想开几个窗口一起做时，Agent 自动读取当前状态、
  下一步和[并行说明](qrefactorbench/docs/parallel/20260929/README.md)，按当前进度恢复或调整分工，
  简短说明每个窗口可以做什么。任务不是永久固定的，不要求用户回忆或粘贴历史提示。
- 用户用自然语言指定任务即可；ABC 仅作内部目录标识。当前对应关系为：文献/案例 → A，
  代码开发 → B，实验设计/论文 → C。同一对话后续“继续”继承已确定任务。
  尚未分配任务的对话不能假定自己已占用某个窗口；仅询问方案不自动启动研究工作。
- Agent 负责内部切换执行位置：读取对应 `.parallel/20260929/{A,B,C}/2026/FSE/WINDOW.md`
  和当地 AGENTS.md；每次命令明确指定该工作目录，编辑使用该目录下的绝对路径。
  不依赖上一次命令的 `cd`，不把原 FSE 的共享源码当成三窗口运行代码。
  用户无需重开目录、配置参数或管理交接；具体执行规则见
  [隔离说明](qrefactorbench/docs/parallel/20260929/ISOLATION.md)。
- 本入口及原 FSE 的并行说明替代旧副本中“用户必须打开各自 worktree”的启动要求。
  代码隔离、固定版本、运行锁仍须遵守；入口简化不等于共享可变代码或自动完成任务认领。
  论文仅由写作任务编辑原 `paper/`，沿用既有 Overleaf Git，不创建论文副本或自动同步远端。
- 进度、交付和后续分工由 Agent 按现有文档职责维护，不把目录/Git/协调操作转交用户记忆。
