# 下一步：检验行为要求与收益判断的耦合

状态：N-059提出的研究假设与有限诊断计划；不是已接受贡献或冻结实验协议。
用户已委托方法选择，不要求其先选agent架构。当前可继续做已有材料的静态证据诊断；
正式新案例、gold/split、优势主张等仍遵守既有边界。

## 拟回答的问题

在Search/Grover与Optimization/QUBO范围内，从原程序行为要求出发，联合推导
可接受的替换方案及完整成本，是否比“先生成、再检查、再估价”的强组合更准确地
判断是否值得迁移，并产生满足原需求的实现？

这里的合同指可观察行为要求：输入范围、输出含义、精确度、并列选择、失败处理和状态。
不假定每项都能自动证明；动态测试、有限穷举、形式证明与未知必须分开。

## 可能的新机制，而非只连接现成工具

1. 从候选片段及调用上下文推导可检查的行为义务，保留来源与未知条件。
2. 将义务作用于方案空间。例如“任意见证”不满足“指定并列见证”，
   要生成额外比较/规范化/验证步骤，或淘汰该方案。
3. 与上述步骤同步推导成本：构造与数据访问、oracle可逆实现、重复调用、采样、
   解码、经典验证及回退；相同工作负载上的摊销口径保持一致。
4. 在明确假设下排除不能满足合同或成本被经典方案支配的候选；其余进入估计/验证。
   不把对有限候选的淘汰说成“没有任何量子算法”。

拟议技术核心是**行为义务改变搜索和成本传播的规则**。程序切片、反例反馈、
SMT、类型检查和代价分析本身均不是新技术；必须证明上述耦合带来独立增益。
若普通后置检查加资源估计即可取得相同结果，应放弃或改写此机制主张。

## 先做一个小而明确的诊断

只使用现有材料，不新增正式母问题、不改历史分数：

| 材料 | 对照条件 | 要查清的具体问题 |
|---|---|---|
| N-054已有pivot秩QUBO | 原扫描 vs 先计算秩再编码 | 正确编码的构造是否已执行原任务的关键工作？这种开销能否由现成成本模型直接发现？ |
| N-058 C01文本匹配 | 原tie/junk规则 vs 简化的任意最长匹配 | 补回原行为所需步骤是否改变候选及成本？不能把简化任务当原API替换 |
| N-058 C02闭合TSP | 精确闭合tour合同 vs 近似QAOA候选 | 验证可行性不等于证明最优；为满足精确合同增加什么义务？许可近似只能作为明确不同条件 |

三个材料只是诊断探针，不是新benchmark，也不足以支撑泛化。其已被开发者阅读，不能
改称保留集。不得为了出现收益随意放宽合同或挑选有利规模。

产物应为逐条映射：**源码要求 → 既有方法能处理什么 → 尚缺什么 → 最简单修补 →
修补后是否仍有研究问题**。每项附具体位置和可核查例子；没有差异就记录无差异。
成本缺参数时先列符号表达式/条件，不编造设备校准或交叉点。

## 必须战胜的基线

| 基线 | 用途及公平性 |
|---|---|
| 原程序＋适合该任务的强经典算法 | 控制“原实现很慢”造成的虚假收益；相同正确性/质量、输入和成本口径 |
| C2Q原生支持路径 | 直接相关自动转换参照；超出支持域单列，不能全部算算法失败 |
| QPipe式生成、修复与验证 | 现有agent方法参照；原生NL输入与我们源码输入分别记录，适配版明确改动 |
| 现成生成器＋通用合同检查＋QuaST/Predict类选择＋编译估计 | 最关键的组合基线；相同候选库、信息、经典竞争者与预算，不故意遗漏对手可合理得到的信息 |
| 上述组合＋人工正确合同 | 区分问题主要在合同恢复还是后续方案/成本推导；不是可部署自动系统成绩 |

不能声称已经跑通这些基线：QuaST代码获取受限、Predict原模拟器依赖QLM；
替代实现需标注“依据论文重实现/适配”，不能标成原作者复现。

后续消融应围绕机制：移除合同传播、移除合同引入的额外成本、仅后置检查、
统一所有基线的经典优化能力；默认不以agent数量做主要消融。
未来指标至少区分错误量子推荐、正确拒绝/未知、满足合同的覆盖率、总开销；
若尚不能实测优势，只评价条件判断与预测，不能定义人为“优势gold”。

## 放弃条件与备选

- 若三个探针全被现成组合自然解决：它们只能作为测试，不能支撑新方法；扩大只读
  反例检索或改变选题，不继续给同一例追加LLM调用。
- 若缺口只在未写adapter：这是实现缺口，先承认，不包装成技术边界。
- 若只会拒绝所有量子方案：需有满足合同的正向覆盖和适用边界，拒绝率不是成功率。
- 若效果仅来自额外token、人工规格或更强经典算法：控制这些条件后再判断方法贡献。

次选方向是**已有成本模型在新工作负载/硬件条件下的可靠推荐**。QuaST已做不确定性，
故必须有额外的校准/更新机制和跨分布证据才成立；它需要更多真实数据，现阶段不优先。
仅做“源码→QUBO→Qiskit”的产品集成有使用价值，但此次不推荐作为FSE技术主张。
