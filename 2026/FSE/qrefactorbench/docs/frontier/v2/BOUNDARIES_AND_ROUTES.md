# 技术边界、候选突破口与验证方式

本文件回答“以现有技术能推进到哪里”，不按本仓库当前工程能力划线。
研究目标保持不变；以下是三条可推进的技术路线，不是三个互斥的新idea。

## 1. 先把完整目标变成可判断的问题

给定程序P、工作负载W、硬件H、输出质量/行为要求C，对有限可构造候选集合A中的方案，
判断哪些满足C，哪些能在H执行，以及相对合理经典竞争者是否有收益。最终交付包括原软件
调用方式下可运行的混合实现，以及建议适用的条件。这个表述是当前可研究接口，不把
“在A中未发现”解释成“不存在任何量子算法”。长期可以扩大程序、算法和硬件覆盖范围。

必须区分：已证实的映射、已验证的实现、条件收益预测、指定机器上的实测收益。
不能为了让系统总能回答YES/NO而把未知写成NO；也不能把有意义的未知处理当成全部贡献。

完整成本至少应包括：

```text
单次部署成本 / 预期复用次数
+ 每次输入准备与编码
+ 各轮(经典控制 + 通信 + shots × 单次量子执行)
+ 解码、质量检查及必要回退
```

分别报告纯执行、含通信服务、含排队/冷启动等口径；不要混在一个“量子时间”里。
Agent生成与离线训练的成本也记录，但是否摊入部署指标需在协议中明确。
上述分解是分析框架，不是本次拟合出的模型；各项不是互不重叠时需要重新界定，避免重复计费。
当相同质量、输入分布和成本口径下候选优于所选强经典竞争者，才报告该范围内的收益。
端到端分析的必要性可参见[Dalzell等](https://arxiv.org/abs/2310.03011v2)；本次仅摘要级核查该综述。

## 2. 当前手段与边界

| 层次 | 已有手段 | 尚不能直接保证 | 对我们的研究意味着什么 |
|---|---|---|---|
| 计算识别 | AST/依赖分析、符号执行、模式检索、LLM解释 | 从任意动态语言程序找全所有有用量子机会 | 研究受限但更真实的源码范围，明确覆盖和误识别，而非要求万能 |
| 映射与生成 | 算法库、QUBO/oracle编译、约束合成、工具修复 | 任意经典算法都有有效量子加速版本 | 在已知原语及可检查变换内发现更好的对应关系 |
| 行为保持 | 差分测试、小规模穷举、受限等价/概率性质验证 | 无限输入域的通用自动全行为判定 | 给出可验证子域、边界与未知；验证方法本身可成为改进对象 |
| 硬件适配 | 编译、布局、分解、误差预算、噪声建模 | 任意问题都能在指定QPU上达到所需精度 | 联合改变方案和执行配置，测量代价；资源不足时解释限制 |
| 收益预测 | 经验模型、资源估计、采样/质量模型 | 从小模拟无条件外推真实大规模收益 | 评价校准、分布变化与错误决策；给参数条件，不能编造交叉点 |
| 实用优势 | 明确任务、竞争者、质量与设备下的比较 | 有限实验排除所有更强经典算法 | 持续更新经典基线；区分经验优势和复杂性定理 |

硬件约束不是统一的“时代判决”：只有量子比特数不足以描述能力，需连通性、原生门、
可执行深度、误差、测量/复位时间、服务开销等。当前本调研没有指定并测量用户某台QPU，
所以不判断那台机器上某程序必然有/无优势；这不妨碍完成前沿研究与方案设计。

严格理论边界也要限定模型：

- 对允许无界计算的程序，若能总是判定P与“直接返回0”的程序全行为等价，就能通过
  “先模拟任意计算，再返回0”的构造决定其停机，产生不可判定性矛盾。这是经典可计算性
  结果的推论；参见[Turing原文](https://www.cs.virginia.edu/~robins/Turing_Paper_1936.pdf)。
  它限制万能的全行为判定器，不限制有界域检查，也不是量子收益判定的一般不可判定性证明。
- [BBBV](https://arxiv.org/abs/quant-ph/9701001v1)给出黑盒oracle模型中的限制。
  无结构搜索的平方级查询改进不能靠换agent变成该模型下的指数级改进；
  若程序具有可利用结构，则要另分析，不能用此结论排除结构化算法。
- 没有已知方法不等于已证明不可能。任意任务的最优量子算法发现、与所有经典算法的
  普遍优劣关系仍不能从这些系统和有限测试中得出；我们无需先解决它们才能推进目标。

## 3. 路线A：从真实源码恢复可替换的计算——建议首先诊断

**前沿起点：** C2Q分类/实例提取、Yamato相似性匹配、QPipe需求解析；Road显示真实迁移
仍依赖专家做计算分解。这些证据支持先研究源码到问题模型的桥接。

**候选技术：** 用依赖关系确定候选区域及其输入/输出，形成包含变量域、目标/谓词、
状态与精度约束的计算表示；LLM提出若干算法映射，由可检查变换和反例筛选/细化表示。
变换可以识别不同代码写法表达的相同计算，也要保留会改变语义的差异。
这是机制设计方向，当前尚无实现或新颖性证明；不是给模型增加一份词法目录。

**必须对照：** 原生支持范围内的C2Q；Yamato式AST匹配重实现；检索增强LLM；
QPipe式工作流的明确源码适配版；带同样候选库、信息和预算的程序分析组合。
不能将不支持某输入格式的原工具直接记成理解错误。

**验证进步：** 在来源独立的程序上，正确候选覆盖和映射可检查率提高；已有经典/量子
可选方案都保留；输出能够被后续生成器和估计器消费。统计单位是程序/谱系，
不是同一函数的数百输入或改名版本。去掉依赖、可检查变换、反馈分别消融。
若增加覆盖只来自更多token/人工规格，就改进机制并重新控制比较条件。

## 4. 路线B：指定硬件上的方案搜索与完整收益判断

**前沿起点：** QuaST/Predict已做成本、质量和配置选择；C2Q/MQT已做量子后端选择。

**候选技术：** 联合搜索替换范围、数据表示、量子算法、精度/采样和经典后处理，
将原程序依赖产生的构造、数据访问及验证成本传播到方案层；用可信下界排除被支配方案，
把有限试测预算用于最可能改变最终决策的候选。预算分配、联合搜索和下界何处有新意，
需要与相近优化/算法选择方法进一步在实现和实验上区分。

**必须对照：** QuaST/Predict式选择＋相同完整成本输入；通用搜索或标准贝叶斯优化；
先生成后估价；可用的强经典求解器。对手应获得同样的硬件信息和质量目标。

**验证进步：** 降低错误量子推荐与选择损失，同时保留有用的量子候选覆盖；
比较预测误差、测量/搜索成本和最终程序的端到端表现。跨工作负载/设备的验证才能支持
相应泛化主张。模拟器用于生成/正确性和模型诊断，不当作QPU加速时间。
若简单补足成本字段已解决问题，复用这部分能力，继续改进覆盖或决策；目标保持不变。

## 5. 路线C：可用混合程序的生成、错误定位与修复

**前沿起点：** QPipe已做多阶段修复与核对；CORK/QSynth/HPS分别提供受限识别、合成、
混合推理；通用软件迁移也有LLM＋符号验证。

**候选技术：** 将原源码要求、编码、量子核和解码之间的对应关系变成可检查义务，
区分错误发生于需求提取、编码、量子求解还是经典后处理，据此定向修复。
重点是避免在错误formulation上求出了正确数值，及处理测量分布、边界状态和回退行为。

**必须对照：** QPipe式审查＋经典oracle；普通差分测试修复；人工正确问题模型；
相同预算的通用反例修复。不能假设“检查器存在”就意味着提出了新验证技术。

**验证进步：** 交付原调用方可用的混合实现，区分编译/运行/行为通过，
测量错误定位和修复收益，并记录未知和验证开销。移除分层定位或跨边界义务的消融
应显示该机制作用；不能只增加多agent数量。

## 6. 三个已有材料的静态诊断结果

本节实际完成的是对既有源码档案和报告的比较推理；**没有向外部系统投题**，
所以不能声称下列现象是C2Q/QPipe/QuaST的实测失败。

| 材料及定位 | 已有证据 | 最简单的现有技术处理 | 对路线选择的意义 |
|---|---|---|---|
| [N-054秩QUBO](../../../pilot/enhancement/rank-qubo-audit-v0.1/REPORT.md)“验证与实际限制” | 全秩构造为m²对遍历，零秩已暴露原扫描答案；有限域公式正确 | 静态复杂度/数据依赖检查＋记录构造成本即可揭示该具体冗余 | 是收益诊断负向控制，不足以单独支撑新成本技术；需要更复杂方案选择证据 |
| [C01文本](../../../pilot/new_mother_candidates/v0.1/C01_TEXT.md)；固定`difflib.py`266–303、363–417 | 默认autojunk、junk扩展和tie影响结果，不能简单识别成长公共子串 | 人工提炼受限合同＋差分测试可抓已知差异；源码上下文自动恢复的效果尚未测 | 优先支持路线A/C诊断；不能拿已知例子的修复冒充通用识别能力 |
| [C02闭合TSP](../../../pilot/new_mother_candidates/v0.1/C02_TSP.md)；固定模块92–125 | 有返回0的边、精确成本和解重建；合法路径不等于最优路径 | 现有约束编码＋经典小规模最优oracle可检查；大规模精确认证需另分析 | 支持A/B/C交界处诊断；QAOA低能样本不足，但不能据此排除所有量子TSP路线 |

这一诊断也纠正N-059的排序依据：三个材料不能证明“行为合同与成本”已经是最好的唯一
突破口。它们说明源码解释、正确替换和收益核对都值得测。原十例与这些候选的纳入、
标签和split保持原状态；已读材料均属开发证据。

## 7. 面向FSE还需补的研究证据

[FSE 2027官方CFP](https://conf.researchr.org/track/fse-2027/fse-2027-papers)评价原创性、贡献重要性、
可靠性、适用的评价、表达及相关工作比较。下表是我们依据这些标准提出的研究要求，
不是会议规定必须采用某种模型、基线数量或真机实验。

| 要证明的事情 | 当前证据 | 后续应补什么 |
|---|---|---|
| 解决有价值且未被充分解决的软件问题 | 本次前沿＋源码范围核查、Road迁移案例 | 针对所选瓶颈的直接对照与需求；不以“端到端”三个字代替差异 |
| 技术机制有效 | 旧局部实验，尚无稳定跨程序增强证据 | 实现选定机制，与强组合及同预算基线比较；机制消融 |
| 原程序迁移可用 | 当前主要是机会识别/条件映射和局部检查 | 独立规格/参考审查；生成实现与原调用链测试；随机输出需统计或形式条件 |
| 结论可泛化 | 十母例及开发暴露材料；三份候选未正式纳入 | 来源/谱系隔离、多种真实计算、失败与未知完整保留；不能把输入重复当独立程序 |
| 收益建议可信 | 无当前硬件上的端到端优势结果 | 指定工作负载、质量、强经典基线、成本口径与硬件；预测和实测分开 |
| 可复现且主张准确 | 已有冻结输入/日志/哈希和论文提案 | 后续机制与基线可复现；数据可用性和限制说明；不将本次静态阅读写成性能复现 |

FSE并不要求我们先证明通用量子优势才允许研究自动化工具；论文主张有多大，证据就需覆盖多大。
贡献可以是更好的识别、决策或迁移机制，并明确它如何推进完整软件目标。
