# 按完整目标核查现有能力

阅读截止2026-09-28。沿用[N-059证据](../EVIDENCE.md)及其固定源码，本版补充源码卸载和
真实软件迁移路线。**论文报告、静态源码事实、本项目实验与研究推断分别表述。**
下面“未展示”均指所读版本/实验范围，不是断言该工具永远不能扩展。

没有统一输入和评价条件，不能用这些论文成功率排出总冠军。我们应按环节采用最接近的
参照，并另外比较一条合理的组合基线。直接对照集含8项；Q-READY与QPipe有作者重叠，
不能作为相互独立的成功复现。

## 公开实现的具体核查点

以下路径均相对[N-059源码归档](../../../pilot/frontier_audit/20260928/README.md)。

| 位置 | 直接观察 | 可支持的判断／不能推出的结论 |
|---|---|---|
| C2Q `src/parser/parser.py:116–159` | 预测类别，AST收集变量/调用，按类别提取实例 | 支持受限识别＋提取；未证明任意程序自动理解 |
| 同文件184–211 | 尝试第一个可转换图值；全部失败时返回随机5节点图 | 该路径不保证忠实提取；没有运行案例，不能报告其发生频率或整系统错误率 |
| C2Q `src/recommender/recommender_engine.py:950`起 | 输入电路，使用固定shots/iterations配置比较量子设备 | 可作为后端参照；单靠此函数不能判断原程序比CPU快 |
| QPipe `pipeline/stage_global_review.py` | reviewer读取原需求、解析结果、方案、编码和代码 | 作者确有需求审查；不是“仅语法检查” |
| QPipe `pipeline/stage_verify.py:94–102` | 数值参考来自`combined.instance` | 验证生成实例的数值；仍要独立确认实例和原任务相符 |
| QPipe `knowledge/classical/solvers.py` | 小Hamiltonian对角化、≤20变量QUBO穷举 | 明确有限可检查域；不能推广为任意规模的廉价自动认证 |
| Predict `algorithm_selection_framework.py:808–841` | 依据目标/约束和可用预测模型组成候选集合 | 已有可扩展配置选择，不应通过弱化对手制造新颖性 |
| Predict `csvs/classical_approximation_benchmark.py` | MaxCut SDP等经典近似计时 | 强基线需考虑这些已有经典对照；不是只与暴力枚举比较 |

这些是源码层面的支持域/风险证据，不是实际运行失败。没有下载权重、安装依赖或运行上游系统。

## 新补充论文对判断的影响

**Yamato：** [作者存档PDF](https://jxiv.jst.go.jp/index.php/jxiv/preprint/download/2811/6858/6255)
含发表DOI。§4使用预配代码模式库、Deckard/CloneDigger和Qiskit；§4.2给AST相似度阈值95%。
§3–4明确接口不一致时可能要求用户调整；§5是eigenvalue solver卸载示例，报告15.7秒。
这是作者计时，未在所读评价中建立同质量的强CPU比较；Azure服务名不足以核实具体QPU、
shots、校准或误差。没有找到可固定版本的整套系统代码，不能算已复现。
它说明源码片段自动替换已有先例；推进点可在语义支撑的候选识别、接口保持和收益决策。

**Road：** §5记录从专家识别、数据编码到集成/差分测试的链条；§6提出自动识别和混合变体
管理等后续方向。我们据此把“从真实软件恢复候选计算”重新列为优先研究入口。
这篇工作提供问题来源和迁移过程证据，不提供一个可直接排名的自动agent。
正文中的历史硬件规模等表述不当成2026年的设备事实；其算法速度说法也未在本次复核。

## 可以复用的邻近技术

| 技术/来源 | 输入前提与用途 | 不能自动替代什么 |
|---|---|---|
| [QUASAR](https://arxiv.org/abs/2510.00967v1)、[QuanBench+](https://arxiv.org/abs/2604.08570v2) | 量子任务/电路生成、执行反馈与修复 | 从原经典软件得到正确计算规格及完整收益比较 |
| [Q-Bridge](https://arxiv.org/abs/2603.27836v1) | 限定ML程序转换与任务质量评估 | 通用原API等价；其ML指标不可直接当迁移速度 |
| [QSynth](https://doi.org/10.1145/3632901) | 受限规格驱动的量子程序合成 | 自动恢复任意源码规格，或证明硬件收益 |
| [Hybrid Path-Sums](https://arxiv.org/abs/2604.24578v1) | 已有混合程序的符号表示、重写和性质/等价推理 | 任意Python支持或量子优势判断；本次仅摘要和方法入口阅读，未审实现 |
| [Qrisp/Jasp](https://qrisp.eu/reference/Jasp/Ported%20Features.html)、[MQT Predictor](https://doi.org/10.1145/3673241) | 已写量子/混合程序的编译、设备与编译路径选择 | 自动发现原软件中的新量子算法 |
| [Microsoft QRE](https://learn.microsoft.com/en-us/azure/quantum/overview-resources-estimator) | 指定算法、容错硬件与误差参数的资源估计 | 当前噪声设备的实测成本，或未经指定的用户硬件 |

通用软件迁移也已有LLM＋验证路线，例如[Heimdall](https://arxiv.org/abs/2605.25411v2)
（本次摘要级阅读）。所以新机制必须解释量子映射、随机输出或混合边界引入的困难，
不能仅把通用代码修复流程换成量子任务。用户提供的agent书借鉴及消融原则已记在
[学习笔记](../../AGENT_WORKFLOW_LEARNING.md)，书的实验不作为量子领域前沿证据。
