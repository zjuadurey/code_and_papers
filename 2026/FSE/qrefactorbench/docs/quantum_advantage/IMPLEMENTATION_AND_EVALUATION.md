## 逐候选证据卡（供后续填写）

以下是 Markdown 工作模板，不是新增机器格式、gold 或模型输入。空项统一填 UNKNOWN 并注明原因。

| 项目 | 必填内容 |
|---|---|
| 身份与范围 | case/候选 ID、源码版本/哈希、输入域、实例族、所替换区域和周边依赖 |
| 合同 | 输出、tie/顺序、异常、副作用、精确性；ε/δ 若适用，写依据；不适用则解释 |
| 量子路径 | 具体算法、oracle/编码、求解与解码、重复次数、经典回退触发条件 |
| 语义证据 | 定理或检查器范围、反例、未覆盖域、参考审核者及独立性 |
| 经典对照 | 原实现、合理优化或有竞争力替代；版本、参数、硬件、预处理及调优预算 |
| 资源假设 | 物理/逻辑 qubit、辅助位、门与深度、硬件/纠错模型及来源 |
| 成本分解 | 准备/预处理、量子执行、经典控制、通信/读出、验证/回退、复用摊销 |
| 收益问题 | 预先指定指标、质量与成功条件、规模/实例范围、比较单位 |
| 证据方式 | 数学证明 / 模型预测 / 模拟测量 / 硬件实测，逐项区分 |
| 结果与限制 | 优势/无优势区域、未知参数、敏感性、失败/超时、仅相对哪些基线成立 |
| 可复现性 | 配置与 artifact 哈希、环境、命令、原始日志、分析版本、实际审核记录 |

## 递进工作与停止点

1. **候选合同评审：** N-058 三份档案仍按原队列处理，同时标出收益问题和缺失信息。
   不能为凑优势正例而改变原 API 合同、选题或标签。
2. **形成可审核估算方案：** 选择一个具体候选、经典基线、硬件 profile 与主收益指标，
   先核对算法适用前提和来源全文。完成条件是成本项可追溯、未知项显式，而不是算出 S>1。
3. **协议与实现：** 具体科学假设/正式评分需评审；通过后才实现估算或实验。
   记录确定性测试、错误对照、边界输入与成本项完整性。例：遗漏返回路径或 oracle 构造时应暴露不完整性。
4. **运行与分析：** 按批准范围冻结实例、基线、预算、超时与质量目标；保留所有结果。
   区分开发实例与独立评测，报告参数敏感性与测量不确定性，不事后筛掉不利实例。
5. **论文主张审核：** 每一项收益措辞绑定证据卡和原始 artifact，按 [写作说明](../../../paper/notes/QUANTUM_ADVANTAGE_CLAIMS.md) 限定范围。

以上不是立即执行全部步骤的授权。当前无新 QPU、付费服务、依赖安装或新模型实验；
D-035 的同方向订阅额度不等于授权新的优势主指标、硬件条件或科学标签。
硬件不可得时可以停在透明的条件预测，不把模拟或预测改写成实测。
