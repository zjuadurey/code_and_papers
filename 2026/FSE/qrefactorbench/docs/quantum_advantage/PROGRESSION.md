## 如何判断是新技术进步，而不仅是合理拼装

待检验假设：从原合同提取的义务**参与计划搜索及剪枝**，能比“生成后验证＋单独估价”
更可靠地找到可采用方案，并减少无效方案的构造/验证工作。这是机制假设，尚未冻结论文贡献。

| 对照/消融 | 要区分的问题 |
|---|---|
| 支持范围对齐的现有方法＋普通合同检查＋完整成本工具 | 合理工具组合是否已足够；不能只打弱prompt |
| 同一模型/预算，合同义务只用于末端检查 | 义务参与方案搜索是否优于事后拒绝 |
| 保留合同搜索，暂不使用成本引导 | 成本是否改变所选计划，而非仅解释结果 |
| 保留成本引导，去掉first/absence细化 | 是否产生便宜却改变行为的推荐 |
| 保留全部义务，去掉证明器/经典方案选择 | 结构化证明或更强经典路线是否必要 |

所有实验组最后都用同一完整合同与端到端账本评估；消融不意味着降低研究目标。
评价应覆盖错误推荐、正确保留经典、条件未知、有效迁移，以及生成/验证总成本；
最终正式指标、参考审批和独立测试集需另行确定。已暴露lit-005仅作开发诊断。
若普通组合同样有效，应诚实复用并继续寻找缺口，完整idea和合同/收益标准始终保留。

## 现有技术能做到哪里

| 范围 | 当前判断 |
|---|---|
| 有限Boolean合同/谓词与可逆oracle构造、小规模等价核对 | 现有技术可以推进，本轮已有局部实现 |
| 精确SAT、prefix可满足性、不可满足证明与检查 | 有成熟技术可复用；当前软件适配/实测未完成，不是科技不可能 |
| 给定硬件/编译/噪声/工作负载的条件资源与成本预测 | 现有技术可做有假设估计；未知参数不能靠LLM补成事实 |
| 任意程序、任意未来量子算法的完全优势判定 | 本项目不能承诺；需限定程序类、算法库、合同及证据范围 |
| 在用户现有设备上保证任意经典任务获益 | 无此保证；正确结果可以是保留经典或证据不足 |

本轮不新增“科技做不到”的普适定理，也不把缺依赖、未实现或缺校准当成理论限制。
