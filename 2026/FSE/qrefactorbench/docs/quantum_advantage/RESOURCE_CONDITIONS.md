# 从经典程序推导值得量子化的资源条件

日期：2026-09-28。研究者已认可的研究方向，见[D-041](../../DECISIONS.md#d-041-infer-resource-conditions-for-beneficial-quantumization)。
本文记录问题表述、输出与后续工作；不代表已有自动估算器或新的优势实验结果。

**后续D-043已明确并执行替代证据路线：** 小规模核验→构造/算法公式→大规模资源和收益条件。
[实际结果](../../pilot/benefit_analysis/maxcut-formulas-v0.1/REPORT.md)已覆盖100/200/500逻辑qubit，
不分配这些规模的状态向量；45组小规模核验与11次QDK调用已完成。
含精确回退的成功率门槛和成本条件已可计算，见[推导](../../pilot/benefit_analysis/maxcut-formulas-v0.1/DERIVATION.md)。
拥有目标规模设备不是前提；大规模成功率/强经典耗时/证书成本缺失时输出明确参数条件。

后续N-063已实现[资源估算与成本反馈工具](RESOURCE_WORKFLOW.md)，复用微软SDK，
实际联调通过；尚未实现从任意经典程序自动推导收益条件，本文的研究边界继续有效。

## 研究者提出的转向

研究者原话：

> 原来的想法：输入原始程序和当前有的逻辑比特数，输出是否值得量子化
> 这个过程肯定有一个端到端时间的粗略计算啥的
>
> 那可以改成：输入原始程序
>
> 输出有多少逻辑比特数等量子资源时，值得量子化，你觉得呢？

讨论明确资源条件、规模依赖和证据边界后，研究者回复：

> 我觉得很合适，记录这些信息到quantum_advantage doc里

接受的新表述是：**输入经典程序，输出保持原程序行为时，采用什么量子方案，
在什么问题规模和量子资源条件下，预计获得端到端收益。**

这与原目标衔接：先求出值得量子化的资源条件，用户现有设备成为待检查的一个配置。
有依据时生成可用量子/混合程序仍是终极目标；不把工作缩减为孤立电路的qubit计数。
行为合同与端到端收益继续是核心判定依据，贯穿方案生成、选择和验证。

## 输入与输出

“只输入程序”可以是用户入口；分析仍需明确工作负载、原行为要求、经典对照与硬件模型。
能够从源码可靠取得的信息直接恢复；缺少规模或实例分布时输出参数化结果，不暗填默认规模。
经典机器/算法、调用频率、允许误差等假设需要显式标注；不能把新增近似许可当默认设置。

| 输出 | 应回答的问题 |
|---|---|
| 候选迁移方案 | 原程序哪部分替换、使用什么量子算法，经典周边与回退如何保留 |
| 逻辑资源需求 | 逻辑qubit、辅助位、门数/类型、深度、调用和重复次数 |
| 硬件性能条件 | 门/测量速度、可靠性、控制与通信等需满足什么条件 |
| 规模与工作负载条件 | 对哪些输入类别、规模、调用频率或复用方式成立 |
| 端到端收益预测 | 相比哪个有竞争力经典方案，完整任务预计收益及不确定性 |
| 证据与边界 | 行为依据、参数来源、理论/估计/测量分别是什么，哪些仍未知 |

输出应为**资源条件集合或取舍关系**，不默认存在唯一逻辑qubit阈值。
同样数量的逻辑qubit，操作速度、算法深度和执行可靠性不同，收益可不同。
更多qubit可能用于并行、辅助空间或更快的算法实现，但不会自动消除全部准备/验证成本。
若要输出物理qubit要求，须另给纠错、原生操作、连接性及逻辑到物理映射假设。

## 核心计算：由收益约束反推资源条件

以运行时间为当前讨论示例；其他收益指标需要另行固定比较条件，不能事后挑选。
设P为原程序，x为实例或明确工作负载，A为具体迁移计划，H为资源与性能配置，B为经典对照：

```text
R_A(P, x; B) = { H |
    A满足P的行为合同，
    A在H的资源与可靠性约束下可执行，
    T_hybrid(P, x, A, H) < T_classical(P, x, B)
}
```

对分析过的候选计划分别报告区域和假设；其并集只覆盖该候选库，不代表所有可能量子算法。
按规模n表达时须注明实例族/分布，不能把同规模的不同实例当成同一耗时。
现有设备H0是否值得采用，就是检查它是否满足某条有证据支持的条件。
资源参数之间的物理可实现关系也必须保留，不能独立调成任意乐观组合。

T_hybrid继续包含准备、经典控制、量子执行、通信、读出/解码、验证/回退；
编译与复用摊销明确，shots/重试不重复计费，有重叠执行按调度建模。
经典侧同样计入预处理与输出要求。完整账本见[EVIDENCE_FRAMEWORK](EVIDENCE_FRAMEWORK.md)。

可以先粗估筛选，再细化接近收益边界的方案。若成本区间跨过盈亏边界，报告不确定；
不能让LLM补出精确设备常数。允许三类结论：预测有收益的条件、受限范围内无收益、证据不足。
“没有找到收益条件”与“已证明此计划在给定范围内无收益”必须区分。

## 现有技术与我们的研究位置

近期目标是[证据框架](EVIDENCE_FRAMEWORK.md)中的E4条件性收益预测；
理论界、模型预测与E5真机实测分别表述。没有现成大规模量子机也可以研究条件预测，
但假设未来设备的结论不能冒充用户当前设备上的收益。

端到端算法分析已有明确问题/输入输出、实例化oracle、计隐藏成本和强经典对照的方法基础，
见[Dalzell等综述](https://arxiv.org/abs/2310.03011v2)。跨层资源估计已有框架，
见[Beverland等](https://arxiv.org/abs/2211.07629v1)。现有Microsoft估算器也提供qubit与
运行时间的取舍分析，见[官方说明](https://learn.microsoft.com/en-us/azure/quantum/overview-resources-estimator)。
这些支持复用现有资源估计能力，不能据此断言本项目已实现自动收益判断。

值得检验的研究推进是：**从经典源码及行为要求，自动构造并比较迁移方案，
计入完整成本，推导有收益的资源条件。** 单独给已写好的量子程序估资源不是新贡献。
自动化效果及相对现有工具合理组合的优势仍需验证；本次认可问题方向，不预先认定新颖性。

现有[N-061 lit-005分析](../../pilot/benefit_analysis/lit005-v0.1/REPORT.md)只完成局部实例化：
某种串行经典前缀修复方案无加速区间，其他方案与具体硬件收益未知。
它可作为负向校验：系统不能因为增加qubit就为保留全部经典工作的方案编造收益阈值。
原程序行为、参考版本与历史结果保持不变，不为获得正例修改合同。
