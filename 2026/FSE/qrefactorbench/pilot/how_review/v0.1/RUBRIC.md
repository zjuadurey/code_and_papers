# 待审规则：以主张和义务为单位

状态：PROPOSED，尚未替换 evaluation_protocol / provisional_labels。
适用范围：当前 Phase-1 条件计划及相关候选解释，保留 D-014–D-017 的语义。
目的：区分“映射成立”“明确未完成”“提出错误主张”，不奖励篇幅或算法名。

## 四项证据记录

| 项 | 审核问题 | 应保留的证据 |
|---|---|---|
| M 核心对应 | 变量/有限域、约束/谓词、目标是否与选中计算对应？ | 源码、原合同、回答原文、映射推导 |
| E 编码条件 | 系数、惩罚、slack、比较器/判定过程的条件是否成立？ | 具体参数范围、推导、有限测试或反例 |
| C 合同义务 | tie、无解、顺序、异常、精确性怎样保留？ | 分离核心 ground state、输出认证和全程序行为 |
| W 边界依赖 | 候选依赖、触发路径、保留的经典部分是否说明？ | 源码调用/数据依赖、替代边界、接口义务 |

每条原子主张记录：response path/hash、JSON pointer、原文、待检验命题、
evidence_state、evidence_kind、证据路径、适用域、未解决义务、审核身份与成熟度。
试审中一项可以包含多条主张；反例只反驳被检查的分支，不传染到所有替代方案。

`evidence_state`（非分数）：

- `supported`：所声明的狭义主张有相应证据；必须写清只支持什么。
- `contradicted`：有合法输入反例、逻辑冲突或源码反证；需可定位到具体断言。
- `unresolved`：已经涉及但证明、构造、解释或评审尚不足；明确留白不是错误。
- `not_addressed`：任务要求的义务未提及。与提及后承认未解决不同。
- `not_reviewed`：本次未审核；不从没有发现错误推导正确。
- `not_applicable`：该主张在所选条件方案中不适用；需理由，不能替代漏答。

另记 `response_status`、`obligation_status`（条件/未完成/已提供狭义构造等）和
`evidence_kind`（源码阅读、手工推导、有限检查、反例）。`supported` 永远不隐含
整题通过、量子执行成功、全部输入已覆盖或研究者已审核。

## 审核程序

1. 固定原文、输入版本、研究假设与候选范围；先读合同再读模型方案。
2. 把多分支提案拆开；记录变量约定，不能因 0/1 翻转不同就判错。
3. 先核对数学核心，再分别检查合同与接口；替代家族按同一证据门槛审核。
4. 反例必须在合法输入域内，满足回答给出的参数条件；审查者补选参数须标明。
5. 有限枚举记录输入域、数量及检查对象；不把经典求 ground state 当量子求解。
6. 未实现的经典认证/回退仅记录为义务；“可以回退”不能修正错误公式，也不证明收益。
7. 汇总为证据矩阵及未决事项；本版不定义权重、阈值、task_pass 或主排名。

## 必须保留的边界

- D-017：核心结构 YES 不要求已经完成原软件合同的迁移实现。不得因量子采样没有
  精确性保证直接推翻一个成立的核心映射，也不能因 YES 自动判合同满足。
- D-014：结构 YES 需要条件计划。结构未定/NO 的理由仍可审核；不自动要求凭空填计划。
- 多种家族、候选边界合法性按语义审核；行号 IoU 与参考家族一致性只作为原有诊断。
- UNKNOWN 与 NO 分开。practical 需要明确成本/工作负载证据。support 的公开定义
  需要澄清，提议将版本是否提供可验收迁移合同作为给定 metadata，而非让模型猜。
- 不以模型多数票产生 gold。研究者审核及独立注释仍未完成。
- Flash 的截断记录在交付维度；无最终答案时不从 reasoning 生成语义评价。

## 对未来版本的具体设计建议（尚未执行）

1. 开发集：将已观察的十个母案例标明用于规则开发；旧输入及分数保持冻结。
2. 配对变体：固定核心、改变 tuple tie / numeric-mask tie / 任意最优解等合同。
   同一来源/母问题的变体在同一 split，不能增加独立样本数。当前没有新建变体。
3. 保留集：先冻结规则与抽样计划，再建设独立母案例；按来源及算法结构检查依赖。
   改名或换数值不足以声称独立。没有事后挑选能拉开模型差距的题。
4. WHERE：先审现有 A/B/C 提示、范围与预算；B–C 带有提示效应，不能声称纯因果分离。
5. 基线：预先记录 wrapper、工具、预算/超时、重复次数、失败政策、成本单位。
   不假定不同 provider 的 effort 名称或 token 数可直接等价。
6. Agent 假设：测试分析/有限验证/反例反馈能否改善合同正确性。调试检查与最终隐藏
   测试分离；经典完整重算的成本要记录。此处没有确定 Agent 架构或运行授权。
