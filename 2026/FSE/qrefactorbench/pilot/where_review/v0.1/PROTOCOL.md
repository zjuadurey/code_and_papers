# A/B/C WHERE 诊断设计草案

状态：**研究者认可三条件方向；具体区域、审阅标准、运行配置待审；未运行。**
这是两个已有母案例的对照准备，不是新 benchmark release 或新增模型 baseline。

## 研究问题和比较单位

问题：在完整软件功能上下文中，不给位置线索会怎样影响候选发现、边界理解和条件
HOW？WHERE 提名不要求通过 WHETHER；不把保守 practical 判断或缺失实际收益视为
定位失败。条件计划与部署建议继续分离。

| 条件 | 输入 | 可以研究什么 | 不能直接归因什么 |
|---|---|---|---|
| A 核心 | 已有 source-core-003/004 的两个源操作及各自合同 | 基本结构/语义识别 | 与上下文相比长度、命名、API 都不同，A–C 不是纯定位效应 |
| B 上下文＋提示 | 完整 lit-003/004 公共材料，增加一个文件/行范围 | 提示后对依赖、控制条件、条件 HOW 的理解 | 不能用 B 的已给 span 命中率代表自主发现 |
| C 上下文无提示 | 与 B 相同公共材料，去掉唯一位置 cue | 自主提名及边界理解 | 不能把每个 C 失败都归为 WHERE |

A 保留两个功能不同的操作，并非手工抽出唯一“正确目标”；因此 A 是校准条件。
B 提示也不是穷尽答案、不列依赖或预期算法；具体 spans 仍是 AI 审阅提案。
B/C 删除提示后的消息字节相同，共享 TASK、源代码、公示合同、schema 和 contract menu。
条件名、母案例 ID 映射只在外部 manifest 管理；每份消息只带自身 public case_id。

## 原型审阅表，不是自动评分

对每个 **C** 回答分别记录候选覆盖（含漏提名）及额外提名的理由；多候选逐个看，
不强制唯一命中。对 A/B/C 均审阅下列证据，不合并成一个成功分数：

| 维度 | 记录内容 | 不能混同 |
|---|---|---|
| 发现 | 原始 spans、计算意图、提名理由；是否漏掉人审确认的机会 | 因 practical=false 而选择 REMAIN_CLASSICAL 不等于没发现 |
| 边界/依赖 | 内核、输入/predicate/state、调用条件、输出/异常责任分别在哪 | 行重叠高不等于理解对；宽/窄表述可能都合理 |
| 条件 HOW | 是否有具体 formulation、encoding/decoding 与未解决义务 | 非空/详细计划不证明正确 |
| 原合同义务 | 保留 preview/current/report/tie 的证据或缺口 | 提及义务不等于已经实现保持 |

每项用“有源代码支持 / 缺失 / 与源代码矛盾 / 无法判断”作**初步人审记录**，摘录
回答和源码证据；允许不同审阅者分歧。缺失说明不是能力不存在的证明。不设权重、
IoU 阈值、通过线或最终失败分类。原 evaluator 不修改；其 `candidate_correct`
仍为精确 span 比较，不能当成本草案的语义边界正确率。

现有预测格式可用 `candidate_regions` 与 `rationale` 保留这些内容；无新增 schema。
若以后要计算依赖召回，应先定义人审义务清单、可选依赖与分母，再版本化实现。
目前不得用候选草案直接计算“科学准确率”。不为原案例造假想模型输出。

## 什么结果支持什么解释

- A/B 有合理条件映射，C 漏候选：支持发现环节值得进一步研究；不是因果定论。
- A 可理解，B/C 都漏关系来源：优先检查上下文/依赖理解，不归成纯定位失败。
- C 正确发现却无法形成映射：保留 WHERE 成功，单独分析 HOW。
- 三者均表现好：作为基础校准保留，不添加无关代码直至模型失败。
- 仅简单 AST 循环/递归提名就覆盖多数目标：说明复杂发现技术的必要性需要重新审视。
  这个静态对照只是未来备选，当前未实现或运行。

## 效度限制和实验前门槛

1. **人工审阅先于评分。** 确认功能可信性、cue span 与依赖/外围义务；允许多个
   边界，不把人审阅过工作表误写成独立双盲注释。
2. **两例只是协议校准。** 都选自拟正向母问题，不能测完整的无候选特异度或宣称
   自动拒绝能力。未来需要审阅后的无候选、多候选及 WHERE 提名后 WHETHER 拒绝
   控制案例；当前不新造负标签。特别是 B 的提示本身暗示存在值得关注的位置。
3. **B–C 是位置提示干预。** 它也改变注意力分配、候选先验和 token 数，不能宣称
   纯粹分离了定位能力；B 的提示有错则比较无效。提示不向 B 提供额外 HOW 答案。
4. **不要混入旧实验。** TASK 是新草案，依 D-014 请求条件计划，依 D-016允许先提名
   后拒绝；不声称只比历史 baseline 改了一句话。历史输入及输出不变。
5. **独立性。** 六份输入只有两个母案例；同源变体同组分析和以后划分。B、C 的
   case_id 相同，A 使用 core ID，结果必须按母案例/条件分目录，不能用旧 collector
   把全部预测当同一数据集而覆盖或触发重复 ID。此处不修改 collector。
6. **执行协议待确认。** 若以后获准，三个条件同模型/推理预算/限制/可观测配置，
   各新会话、无跨条件记忆/工具/反馈/修复，保留第一次响应与失败。确认是否重复
   采样及顺序控制；单次输出不能区分提示影响和随机波动。记录未知服务端配置。
7. **可见性。** 模型只获得一份 prepared/inputs/*.txt；B 中的提示是显式实验处理，
   不能称完全盲。其他条件没有额外参考标注。不要提供 prepared/evidence、manifest、
   这份协议、人审页或整个仓库。
8. **代表性。** 有来源的内核仍来自合成数据，新业务要求仍是合成；保留原源码名字
   和许可提示。不能由这两例宣称真实仓库普遍困难、真实收益或独家创新。
