# QRefactorBench-v0 pilot — curator entry point

**Preparation record:** the description below predates completed model experiments.
Its statements about absent responses/scores apply to that preparation stage.
Current status and next action are [PROJECT_STATUS](../PROJECT_STATUS.md) and
[NEXT_ACTIONS](../NEXT_ACTIONS.md); the [paired diagnostic](baseline-v0.1/conditional-plan-diagnostic/README.md)
is complete and is not an independent baseline. This curator page is not model input.

This is ten DRAFT synthetic seed programs plus review materials, not a validated
benchmark release. Source programs were written with Codex assistance for this
task; no independent researcher authorship, source repository, license grant or
review is fabricated. source_url=null and license=NOASSERTION preserve unknowns.

The original four infrastructure toys remain unchanged outside cases/pilot/.
The pilot has two search kernels, two optimization kernels, two contextual
positives, two unsupported-hotspot hard-negative hypotheses and two structurally
plausible but unsuitable hypotheses. seed_manifest.json records this private
sampling plan; it must not be distributed to annotators or the model operator.
QRefactorBench-v0 names the pilot, not the software/schema version or a release.

## Separation of facts and hypotheses

- cases/pilot/pilot-NNN/program.py (plus support.py for two cases) is the classical
  artifact. Tests exercise original classical behavior, not a quantum migration.
- public_task.json contains only the software contract, valid inputs and stated
  workload assumptions. These facts must be reviewed by the coordinator before
  distribution; they are necessary inputs to suitability reasoning.
- case.json and CURATOR_NOTES.md contain proposed labels, regions, contracts,
  semantic criteria and reference plans. Every annotation is DRAFT; no one has
  independently reviewed it. Six intended positives have practical_suitability,
  benchmark_supported and expected_decision=null. The two suitability-negative
  judgments are hypotheses, not measured profitability results.
- public_contracts.json is the same DRAFT menu for every case. Its presence does
  not certify a contract, algorithm or case as scientifically admissible.

Two hard-negative drafts use candidate_regions=[] and record rejected hotspots
only in curator notes. D-005 currently requires nonempty regions for REVIEWED hard
negatives. This real protocol tension is recorded in Q14 and D-008; these cases
must not be promoted by filling a fake candidate just to satisfy validation.

The general marked-state oracle requirement is described in
[IBM's Grover tutorial](https://quantum.cloud.ibm.com/docs/en/tutorials/grovers-algorithm).
The candidate optimization execution family comes from the
[QAOA paper](https://arxiv.org/abs/1411.4028). These are background references for
the shared menu, not provenance for our programs or evidence that a particular
case is suitable. Exact classical optimizer outputs still require a scientifically
defensible semantic contract; no approximate threshold is chosen here.

## Prepared materials and regeneration

Current input revision: **pilot-v0.1**. Use `packets-v0.1/annotator_a`,
`packets-v0.1/annotator_b`, `packets-v0.1/adjudication` and `packets-v0.1/baseline`.

See [PILOT_V01_CHANGELOG.md](../PILOT_V01_CHANGELOG.md) and revisions/pilot-v0.1/
for exact public-text changes, old inputs and revision hashes. A/B receive blank forms and

a file-hash manifest. These are folders, not access-control boundaries: distribute
only the assigned directory separately, outside the full repository. Do not give
the common parent or this curator README to independent annotators.

To create another snapshot in a new directory (existing outputs are refused):

```bash
python scripts/prepare_pilot.py prepare --output /path/to/new-pilot-packets
```

The utility allowlists public fields and source files; it excludes case manifests,
curator notes, tests, draft references, categories and previous annotations.
No model calls or scientific annotations are generated by this utility.
Original task files and source coordinates are preserved. After changing a public
fact, source or prompt, make a new packet snapshot; do not alter a distributed packet.

Independent forms are not case manifests and are not inputs to `validate cases/`.
null candidate_regions means unfilled; [] means an explicit no-candidate judgment.
Use compare-annotations after both submissions, then complete the adjudication
form with evidence and preserve the originals. There is no automatic promotion,
agreement estimate or label merger.

See annotation/instructions.md, annotation/adjudication_instructions.md,
baseline/README.md and failure_analysis/README.md for the actual workflow. No model
responses or scientific performance scores are included. The next human actions
and engineering test evidence are recorded in ../PHASE1_PILOT_STATUS.md.
