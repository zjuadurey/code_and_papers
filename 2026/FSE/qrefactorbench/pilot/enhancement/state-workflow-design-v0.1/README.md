# N-049：反馈信息与可检查主张的离线设计

2026-09-26。**完成25份旧回答的原文映射、5份初稿的分析入口核对，以及16份拟议对照
输入。零模型调用；没有新效果结果。** 本目录是D-032委托范围内的事后设计，
不是新运行授权或已实现的下一版agent。N-048的协议、响应、绑定及结果保持原样。

研究目标仍是用程序分析与语义验证增强同一个模型。当前要解决的是：反馈中的哪些
信息可能起作用，以及哪些回答尚不能被检查。先拆清这些问题，再增加工作流步骤。

## 1. “证据不足”分别缺什么

[25行映射](audit/response-crosswalk.json)逐份保留旧判定、原文指针、响应哈希、审核理由
和拟议补问；90处原文锚点核对一致。分类是协调者的**设计分流**，不替代科学标签或原成绩。
这些行属于同一母案例、含同稿修订，不能当成25个独立样本。

| 情况 | 回答数 | 准备采取的动作 | 可支持什么 |
|---|---:|---|---|
| 缺具体选择规则 | 5 | 请求候选域、状态、比较/更新、初始化与顺序 | 判断是否能唯一转录；不能替模型完成算法 |
| 没有候选 | 3 | 提供公开函数目录供分析，允许继续无候选 | 空清单不再被误读为工具确认“没有机会” |
| 整个函数提名、没有计划 | 4 | 分开分析范围与改写对象，先列语法结构 | 函数分析请求不等于整个函数可迁移 |
| QUBO未具体构造 | 3 | 请求变量、目标/系数、约束/罚项界及解码 | 补齐后仍需适合QUBO的检查器；不能强改为Grover |
| 比较措辞有歧义 | 2 | 请求明确运算符、量词及条件 | 避免审核者选一个有利解释 |
| 已有明确局部规则 | 8 | 保留原绑定，无需补问以抬高覆盖 | 其中仍有反例和有限条件，不等于8份正确 |

前四类合计15份，对应原来的证据不足。第5组A/AV检查的是补充Grover主张；它们的主要
QUBO方案也未验证，但不重复计入上表的3份。分类以旧审核为依据，不是自动语义抽取。

拟议补问目前只存在审计文件里，**没有放入下面的16份提示词**。若同时加补问、分析改进
和反例，无法知道哪个变化造成效果。因此先设计信息控制，再单独研究形式信息补全。

补问遵循三个约束：不提供正确运算符或已知失败类型；允许未知、无候选和其它既有家族；
保持Phase-1原输出schema，在既有plan字段提供信息。不能为了适配检查器强制所有回答
成为同一种公式。guard须由模型明确声明；条件外回退、主要计划和附加主张分开检查。

## 2. 分析工具为什么接不住候选

[入口核对](audit/candidate-routing-audit.json)显示：5份初稿的旧分析结果是3份词法清单、
1份由空提名直接产生的空清单、1份不支持结果。旧工具只用`start_line`找种子语句；
`end_line`未参与选取，不能把这个接口称为完整区间分析。

- 第1组提名12–16行。起始行是覆盖12–20行的`for`；词法种子本身已超出提名末行。
  后续依赖出现在候选范围外本来可以合理，但必须区分“候选”“种子”“分析上下文”。
- 第4组提名9–26行，起点是函数定义，旧工具要求单条函数体语句，所以返回unknown。
  不能悄悄改成审核者偏好的第13行，再声称模型找到了正确子区域。
- 第3组没有提名。分析器未分析任何候选；这不是扫描全程序后作出的否定结论。

已用AST只读解析三份公开源文件，生成[函数及直接语句目录](audit/public-source-outline.json)。
目录按源码顺序列出所有顶层函数，不做候选排名，不运行源代码。这验证了提供中性分析
入口的可行性；尚未实现新的范围路由、候选发现或可靠程序切片。

拟议接口保留原始`declared_region`，另记`analysis_scope`和`seed_statement`。
空候选返回`no_nomination`及公开目录；函数级范围返回完整语法目录并等待显式定位；
区间落在复合语句内部时说明边界关系，不把它缩成单行或推断为可迁移。
目录的新增信息本身也是干预，应在未来分析消融中单独对照，不能并入本轮反馈控制。

## 3. 下一轮优先检查哪一种信息有效

建议先做一个**使用历史初稿的反馈诊断**，仍限lit-009 C；不把它称为新的无提示WHERE
测评或独立保留测试。5份旧初稿全部保留，不按结果筛掉难检查的回答。

| 拟议条件 | 初稿数／新增调用上限 | 实际增加的信息 | 配对解释 |
|---|---:|---|---|
| S 自检 | 5／5 | 无观测 | 这次运行的同步基线，不借用旧S作为新对照 |
| C 范围提示 | 5／5 | 旧反馈原有的pivot范围句 | C−S：范围提示包的作用 |
| E 检查摘要 | 5／5 | 相同范围句＋旧检查状态、计数与限制 | E−C：整个检查摘要包的作用，不单称一个状态词的作用 |
| W 具体反例 | 1／1 | 与同稿E完全相同，只增加旧开发反例字段 | W−E：这一次机会中具体失败记录的增量 |

合计**最多16次新调用**，不是新的5份初稿＋修订。W只用于原开发反馈确有反例的第2组，
由已有开发结果决定；其他4组没有可加的反例，E与W将相同，故不重复调用。
因此C−S和E−C各有5组配对，W−E只有1组。不能把W的1份与E的5份比较总体比例，
也不能把条件分流记作丢弃失败；适用机会数本身要报告。

所有条件使用同一公共任务快照、对应原始初稿、同一修订指令、同一模型与输出schema。
唯一变化是观测数组；分支名、旧最终成绩、正确修订、审核补问、分析目录和“隐藏结果”
说明均不进入模型输入。C保留旧句“Reviewer-transcribed pivot selection on finite
development checks only”；这是含pivot方向和检查范围的提示包，不是纯粹一个位置词。
E保留旧检查摘要中的`insufficient_evidence`或`contradicted`等事实及限制。
W逐字保留第2组开发反馈的`first_counterexample`，包括请求、状态、原选择和谓词结果，
没有添加正确更新算法。E删除该字段，不以null或“已隐藏”占位。

输入长短本来不同，不宣称token等量，也不通过填充伪证据匹配长度。
运行顺序草案在5组间轮换S/C/E；第2组W放在该组最前。只有一次W，不能平衡顺序效应。
客户端seed、temperature和服务端模型快照仍未知，不声称确定采样。

[16份准确提示词及哈希](audit/prompt-design.json)已经离线生成。
建议模型仍为Sol/medium、现有订阅；串行、每次600秒、零重试，保留格式/预算失败。
这是**未执行的参数草案**，无授权回执、不含在线执行器；不复用D-033已耗尽的运行目录。

## 4. 怎么评估，哪些比较现在不能做

拟议观察继续使用N-046/N-048的类别：证据不足、歧义、反例、条件内有限通过、无额外
排除的有限通过；所有调用留在分母，另外报告候选/计划覆盖和可转录主张数。
不改benchmark主指标或整题`task_pass=null`的边界。初稿中没有已通过的主张，不能
声称本设计测得正确→错误的退化；新增错误主张要单列。

每份新响应须独立绑定原文，保持`AI_REVIEW_PENDING`，明确主要/补充主张、guard与回退。
全部绑定冻结后才能汇总最终结果；不得从已知修复中替模型补规则。未支持的QUBO继续
未知；不可因主家族不同而只抽取有利的补充主张。人工/协调审核成本单独记录。

此前44个保留状态的结果已经看过，本设计也由其结果启发，**现在只能把这套状态用作
已知回归检查**，不能继续称为本轮未见测试或用来建立泛化结论。不在本轮事后挑选新
难例改善区分度；更强主张需要另外预先确定未见母案例、审核和评测安排。
新调用若开展，N-048旧S/V修订只供历史背景，不混进新条件当同步对照。

即使W表现更好，也只支持一个已知失败、一次配对的诊断；不能证明工具整体有效、
独立WHERE能力提升、组合优于V、完整软件迁移正确或量子优势。反例同时含输入和输出，
本设计也不进一步拆解这两部分的作用。
