## 2. 从合法请求到失败状态

直接追踪未修改的 [kernel.py](../../reference_completion/v0.1.1/cases/lit-009/kernel.py)、
[program.py](../../reference_completion/v0.1.1/cases/lit-009/program.py)；不重写消元、不执行模型代码。
输入检查和初始 residual 通过，inspect 返回正常，solve 才进入候选。所有输入数均有限。
下列列号/索引为 Python 的 0-based；源码行号为 1-based。

| 时点 | 实际状态 / 运算 | 含义 |
|---|---|---|
| col=2，第 20 行 | `1e308 - (-1.0 * 1e308)` 产生 `inf` | 输入有限不是循环不变式 |
| col=3，第 13 行 | 活动列为 `[inf, inf]`，原 max 和文字谓词均选择 3 | Infinity 本身并未使该例的谓词失败 |

新增敏感性输入：在原 5×5 系统外补一个独立单位对角元，其余新系数为 0，rhs=1、current=0。
该 6×6 请求也通过初始检查；浮点消元中的 `0 * inf` 使附加行受污染，col=4 可达
`[nan, nan]`。原 max 选 4，包含自身和排除自身的两种谓词均无标记。
因此，**仅省略自身比较或特判单元素不能解决这里的语义问题**。
这是审核者构造的同母案例事后敏感性输入，不是新的母案例、模型响应、保留集或预注册测试。

普通 2×2 对照的两次 pivot 与旧 5×5 的五次 pivot 均重放一致；新增 6×6 追踪六次。
审核者“首元素作为 incumbent，仅在严格更大时更新”的顺序扫描对照在 13 次状态上均一致。
它是经典语义参照，没有被冒充模型修复或量子 oracle。

## 3. 经典回退能支持到哪里

Sol 的输出解码要求先验证测量索引，未获验证结果则重试或经典回退。原文没有显式排除
NaN；不能替模型偷偷添加“中间量始终有限”的前提来维护公式结论。

- 若在未确认的 pivot 上回到原 `max`，保持相同 rows、控制流和后续算术，可能保留原异常。
  若从完整原请求重新执行经典程序且前段无外部副作用，也有可行回退方向。
  两者均为审核者的充分条件说明，本次没有实现或认证这类迁移。
- 若验证器直接复用错误谓词，NaN 状态下无法验证任何候选；需要保证最终回退，
  不能用无限重试、默认行号或“无解”返回代替原合同。
- 在同一个失败例上提前抛出同文异常，并不能证明任意输入上的异常优先级及输出均一致。
  更不能把“经典回退正确”计成“量子映射正确”或性能收益。

剩余整题义务：输入/异常优先级，inspect/空系统，全部 pivot 及更新次序，回代、
残差/归一化、命名输出与 deltas、无输入修改，以及验证失败时的终止路线。
N-040 的少量精确可表示数值实例没有覆盖任意可达 binary64 状态。
本次只对上述三个请求确认原程序输入未变，未完成全域证明。
