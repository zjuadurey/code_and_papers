# 当前 benchmark 的两模型小报告

2026-09-22。**测试闭环已跑通，但这轮粗粒度指标尚不能区分两模型能力高低。**
有价值的结果是具体方案差异，以及暴露出的标签/任务边界问题。

## 设置与完成情况

使用当前 v0.1.1 的 **10 个母案例、C 条件（完整程序，无位置提示）**，
gpt-5.6-sol 与 gpt-6-astra 各答一次，共 20 次。两者均为 medium，Restricted Codex
CLI 0.155.1，通过现有 ChatGPT 订阅登录，无 API key。耗用订阅额度；CLI 未提供
Pro 配额扣减量，不能用 token 数换算账单。全轮约 17.3 分钟。

每次全新隔离上下文，只提供该案例公开输入；工具禁用，私有参考不挂载。
20/20 完成，20/20 通过严格 JSON、schema、ID 和源码坐标检查；无工具调用、
科学重试或输出修复。两条重复出现的 CLI 启动警告已保留，不计为工具事件。

参考为 **provisional_labels/v0.1，全部待审**：7 个结构 YES，3 个未定；
实际适用性均未定。下面是参考一致性/覆盖诊断，**不是 gold 准确率或整题通过率**。

## 最值得看的四个发现

1. **定位目前接近饱和。** 两模型唯一的正例边界差异都是 lit-004：圈定 25–29 行，
   暂定锚点是 25–30 行；第 30 行负责名字解码，两份文字都识别了该依赖。
   这不是已证实的定位错误。只有 C 结果，不能推断 A/B 无用。
2. **方案的内容比“有无计划”更能暴露差别。** lit-003 中 Sol 选 QUBO、Astra 选
   Grover 前缀存在性搜索；不能仅按家族名判错。lit-004/006 中 Astra 给出具体惩罚界，
   Sol 留有推导义务。这是内容完整度的具体观察，尚未变成经审核的正确性分数。
3. **控制案例需要按区域审核。** lit-009 两者都提名 `kernel.py:13` 的最大绝对值
   pivot 选择，没有把整个线性求解器当作 Grover 算法。Astra 使用改进 incumbent
   的谓词；Sol 使用 first-argmax 谓词并承认 oracle 可能线性扫描。两者均要求精确
   浮点/首索引 tie 和认证/回退。参考原本未定，不能把这次提名自动算假阳性。
4. **`benchmark_supported` 的问题来自评测端与回答端。** 私有参考指已审核迁移
   合同/验收支持；公开 schema 没有清楚解释。Sol 在 lit-005/006 以来源署名判断 true，
   Astra 多以缺乏性能测量判断 null。先明确字段再评能力，不能事后改本轮成绩。

## 能与不能支持的结论

当前 benchmark 已能收集可比较回答、计算机械诊断，并暴露待审分歧，足以用于
**探索性研究和人工审核准备**。这轮不能支持稳定模型排名、负类识别率、HOW 正确率、
整题通过率或量子收益。每题只采样一次；只有 10 个母案例；两模型仍使用 Codex 系统
脚手架，且每模型的内置提示可能不同，并非 raw API baseline。

内容观察由当前 Codex 做 AI 初审，**尚无人类/独立专家验收，未执行任何迁移方案**。
下一步应优先由研究者审核 lit-003 的替代家族、lit-009 的候选粒度，以及 support /
practical 的定义，再版本化形成可判定的 HOW 条件；目前没有充分证据据此定 Agent 架构。
本轮授权已完成，不自动重复调用或扩展到 A/B。

## 复算边界

运行 `collect.py` 会严格拒绝覆盖已有输出，不要原地重复执行；`run.py` 的历史命令
也不是新增实验许可。离线复算可在项目根目录用以下命令，替换占位符并输出到新的临时文件，
无需模型调用：

```bash
/home/audrey/miniconda3/envs/palqo/bin/python -B pilot/provisional_labels/v0.1/evaluate.py \
  --condition C --predictions <predictions文件> \
  --model-id <模型名/medium/codex-0.155.1> --output <新的临时JSON>
```

原始 token usage 已保留在摘要中；reasoning 字段与 output 字段是否重叠未经确认，
不把各字段简单相加作“总消耗”。
