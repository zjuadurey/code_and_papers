## 业务含义与质量定义

原功能是将设备安排到两个维护时段，再报告冲突和调整。设备对的权重表示希望
它们分开维护的重要程度；同一时段就累加该权重。这里是可付出代价的软要求，
不满足某个设备对的偏好不直接使安排非法。当前权重来自合成案例，不是已校准的
金额、停机时长或风险。硬要求包括每台设备恰好安排一次，以及正确的接口和报告。

设 W 为全部需求权重之和，C 为返回安排的冲突权重，C* 为精确最优的冲突权重：

- 满足的要求权重：S = W − C；最优可满足权重：S* = W − C*。
- **质量比例：ρ = S / S* = (W − C) / (W − C*)**，越大越好。
- 同时报告绝对差距 Δ = C − C*，以及 W、C、C*、S、S*，避免只展示比例。

ρ 表示实现了最优方案所能满足的加权需求的多少，不是满足全部需求的比例，
不是一次运行成功的概率，也不等于剩余冲突的相对误差。达到 ρ=1 表示目标值最优，
不自动证明报告字段、并列选择和其它接口行为正确。

全零权重（包括空输入）时 S*=0，不计算除法，比例报告为不适用/null，单独检查
可行性、C=0 和报告正确性。若没有可信的最优参考值，ρ 与 Δ 应保持未知；
不可把当前最好样本当作已证明的 C*。本例有界经典参考可用于离线评测，不能向
被评测量子求解器提供最优答案反馈。

## 保留的软件要求

继承 [v0.1 输入和报告规范](../v0.1/cases/context-001/public_task.json) 的输入域
（0–16 设备、非负任意精度整数权重）、全量校验与 ValueError、不修改输入、每台设备
恰好出现一次、字段类型和顺序。current 仍应正确反映当前安排；proposed 和 changes
必须由**实际返回的安排**正确计算，不能沿用精确参考报告冒充该安排的报告。
允许安排不同意味着不再以精确参考的整份报告相等作为本草案唯一的质量标准。
移动数量仍只用于报告，不擅自加入容量、移动最少或“不改善就不移动”等要求。

v0.1 的全局最优与全局最小并列 mask 联合约束不能直接套到所有非最优安排上；
新选择规则必须明确后才能完成合同。默认 D-015 未被普遍取消：其它案例仍以其
原合同为准，不能因为某算法常输出近似结果就自动放宽要求。
