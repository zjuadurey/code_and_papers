# 任务、判定与隔离审查

2026-09-22。本次先运行基线，再新增兼容的私有版本。发现的主要问题是**证据链尚未
统一**，并非旧评价器已经把所有粗标签分当成语义通过。不能为了突出修复而误述原状。

当前任务主要是 A（机会识别）＋条件性的 B（映射方案），不属于要求提交实现的 C。
输入明确写了不使用工具、不执行代码、不提交 patch。结构 YES 时需给条件计划，即便
最终 REMAIN_CLASSICAL。数学上可表达、在约束下可实现、具有收益证据三层独立；
core mapping 不自动解决完整原软件合同。不能偷偷引入“必须产出代码”新任务。

## 原始测试及分数能证明什么

- `cases/**/test_program.py` 和当前来源包对应测试运行可信经典程序，可检查异常、
  排序、全报告、输入不变等行为；**它们没有执行模型文字方案**。
- `pilot/provisional_labels/v0.1/test_labels.py` 有真实有限数学检查，也有构造响应的
  schema、分母、待定值和替代家族检查。后者证明评分工程行为，不是模型能力结果。
- HOW 的 `check_evidence.py` 是审查者转录公式的有限检查，非模型实际迁移程序执行。
- 原 evaluator 的家族/标签一致性和行重叠是粗粒度诊断；文本有计划不等于映射正确。
  现有代码已经保留这个区别，本次以回归测试固定它，并增加实际语义证据接口。
- 当前七个结构 YES 的依据是源码数学关系与 AI 提案，不是七条独立金标；008/009/010
  的 null 是证据未定，不能作为确定负例或“答 null 就正确”。实用性全部未定。
- 别的合法候选区域和家族不能仅因与一个参考不同就判错；本版不为 WHERE 引入新阈值，
  也不宣称自动完成 A 的科学判定。C 的接口、执行、量子过程和资源仍未评测。

## 本次实际修补的可信度缺口

1. 缺少统一的逐题“合同—输入—预期—错误类型”对应：新增 sidecar，保留原合同原文和
   已知/缺失前提，固定检查范围，六题未实现部分明确不计完成。
2. 有反例但缺少统一的可复用主张判定：新增精确多项式/双射解码/真值表/报告检查；
   从顶点覆盖推广复用到最大团，检查所有最优解，避免只挑一个正确 ground state。
3. 尚缺系统的判定器正反对照：每题两个正确/等价对照、至少两个合法格式错误对照；
   原公式的排序错误、漏约束、方向错误、漏锁、极性错误、任意 SAT 解、错位序及漏回执
   都有命名测试。没有靠降低阈值、改标签或删难题提高分数。
4. 不同缺失/失败容易混合：新报告区分候选错误、格式错误、模型预算、基础设施故障、
   证据不足、未运行和审查预算；同时保留逐测试诊断，固定十题分母，无新加权总分。
5. 公式主张可能被扩大为完整计划：要求显式 claim_scope，原文/参数来源绑定；其它
   分支和回退未评测，整题 task_pass 始终为空。

## 可见边界、权限与随机性

现有输入生成与版本测试使用 allowlist，并核对公开 txt 哈希。本次没有把契约 sidecar、
正确对照或新测试加入公开包。模型研究输入只应是指定单份 txt，不能把整个 `pilot/`
传给模型；源码本身属于题目提供的材料，并非需要隐藏的最终参考答案。

历史 GPT 使用隔离工作位置及禁用 shell/browser/agent 等工具的配置，DeepSeek 使用
无工具 API 文本输入。两者都只授权单轮、无修复/反馈；这说明本轮输入/工具政策，
**不等于仓库具备可以安全执行任意 agent 的系统级沙箱**。本地文件、只读约定和 SHA256
不能阻止一个拥有仓库写权限的未来 agent 篡改判定器和哈希。若开放工具或提交代码，
必须另外建立独立的评测进程/文件系统权限边界；本次没有假称解决这个问题。

新判定器只读数据表达式，不接受执行候选代码，不读取认证。路径限制、源哈希和原文
指针检查用于溯源，不能证明人工转录的数学忠实性或审核者独立性。

历史 GPT medium/Codex 与 DeepSeek high/API 推理配置不同；后者输出上限 16384。
历史 seed/temperature 等未提供的值保持 null，不能称为受控确定采样。四模型各一次
回答不能支持稳定排名。新检查完全确定、使用精确算术，没有量子采样、容差、分布
匹配、噪声或资源测试；检验的是映射/报告主张，不能把采样失败混成确定映射错误。
