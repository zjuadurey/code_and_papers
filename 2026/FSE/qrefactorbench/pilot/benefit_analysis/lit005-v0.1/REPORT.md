# lit-005：行为要求如何改变量子方案及端到端成本

日期：2026-09-28，N-061。研究者要求推进已有量子优势调研；这是协调者手工完成的
第一份逐案例条件分析和有限诊断，**不是自动系统成果、正式benchmark结果或硬件优势证明**。

结论：原合同排除了“普通Grover返回任意满足解”的直接替换；用经典前缀枚举修复，
在下述明确条件下没有加速区间。量子最小值搜索或结构化证明仍值得分析，但尚不能推荐迁移。
这份结果说明生成器必须同时考虑行为义务、证明/回退方案与成本，而不是先选算法再补检查。

## 1. 输入、合同和判定范围

输入固定为 [lit-005 v0.1.1](../../reference_completion/v0.1.1/cases/lit-005/)，
六份源码/公开任务/测试/示例的SHA256在[input-binding.json](input-binding.json)。
代码完整定义Boolean CNF和locked赋值，无数据加载oracle或免费QRAM假设。

| 原程序义务 | 对迁移计划的影响 |
|---|---|
| 所有输入先验证，错误抛ValueError，不修改输入 | 保留Python外层，不把无效输入送入求解器 |
| inspect只报告当前违规；合法current必须原样retained | 两条快速路径都不调用量子求解 |
| complete返回按feature顺序、False先于True的第一个满足赋值 | 任意满足赋值不足；需要最小性依据 |
| 无满足赋值才返回None/unavailable | 没测到满足解不能直接推导无解 |
| failed_rules/locked_failures/changes及proposal遵循原定义/顺序 | 不把求解器返回正确等同于整程序合同正确 |
| 未许可算法错误或近似 | 不自行引入δ；错误候选只有经过可靠验证/回退才可采用 |

设锁定变量代入后剩k个自由变量，N=2^k，满足解数M。按原feature顺序重建固定位，
自由位的字典序等同原全向量字典序。常量真/假公式在经典预处理阶段即可处理。
代入锁定和简单化同样提供给经典对手，不能计作量子收益。
本报告选择**同输出要求下的端到端延迟**作为分析对象，不冻结项目正式主指标。

## 2. 四种具体计划与当前结论

| 计划 | 合同与收益判断 |
|---|---|
| Q0：普通Grover/BBHT，验证任意满足解后直接返回 | 不满足first义务；有限超时的未找到解也不是无解证据 |
| Q1：量子提出任意赋值，经典验证，再顺序枚举更小赋值；失败全量回退 | 合同可保持；同谓词、同缩减域、串行且量子成本非负时不比经典枚举更快（§4） |
| Q2：量子minimum finding，把满足赋值映射为rank、其余为N | 更匹配目标，但引用算法提供高成功概率而非当前合同的确定保证；需额外最小性/无解证明，完整oracle还需rank比较逻辑 |
| Q3：量子提出候选，经典SAT/证明检查器证明没有更小满足赋值 | 可设计精确结果接口；证明代价可能较小也可能主导全部运行，尚未实现/测量，不套用Q1的不加速结论 |

Q0、Q2的概率性质依据[BBHT §§3–4](https://arxiv.org/abs/quant-ph/9605034v1)
及[Dürr–Høyer 定理1及证明](https://arxiv.org/abs/quant-ph/9607014v1)。
它们不是所有量子算法的限制；特定promise、精确搜索变体、结构化算法可能改变条件，需单独核查。

### 已落实的oracle

[analysis.py](analysis.py)直接从子句构造相位oracle，不预先枚举答案再编码。
锁定代入、重复literal合并、重言式删除后，对每条子句计算flag；合取flags，施加Z，
再逆序uncompute。多控X使用干净辅助位和CCX链，辅助位跨阶段复用。
对每个基态实现 `|x,0> -> (-1)^F(x)|x,0>`；正确的基态作用及线性性给出理想相位作用。
有限检查本身不证明任意规模实现正确；构造性理由是逐子句的可逆计算和逆运算。

源示例k=3、m=6：**14个逻辑qubit，48 X + 54 CCX + 1 Z = 103门/oracle**。
一般此实现非恒定公式使用 `k+m+1+max(0,m−2,w−2)` 个qubit，w为最大剩余子句宽度。
这是具体未优化构造的门数，不是资源下界、原生门数或硬件可行性结论。
未包含初态H、Grover扩散、测量、Q2比较器；这些必须另计。未运行量子状态模拟器或QPU。

源示例满足赋值为010、011（这里按feature顺序，不是Qiskit打印位序）。
从均匀叠加开始，用理想相位oracle做一轮Grover：
`P(any)=sin²(3 asin(sqrt(2/8)))=1`，两个解等概率，因此 `P(required first)=1/2`。
M=2来自诊断真值表，不能作为运行时免费输入。该计算不是设备成功率测量。

## 3. 经典对照：先确保没有人为削弱对手

1. 原始kernel枚举全部n位，用于合同参考。
2. 相同锁定代入后的枚举，用于Q1同域成本论证。
3. 本地lex-DPLL：unit propagation，最小未赋值feature先分支False，再True；
   单位传播只固定所有剩余解都必须满足的值，因此不会跳过字典序更早的解。
   [实现](analysis.py)已经与原函数有限对照，但它是教学/诊断对照，**不是最强SAT solver**。
4. 正式收益实验仍需有竞争力的增量CDCL/lexicographic SAT路线，同样提供预处理和复用。
   本环境无现成PySAT/Z3，未安装/运行，故不声称已经完成强经典性能对比。

一种精确经典路线：对自由位依次尝试False，在已有前缀下询问可满足性；不可满足才选True。
若起初无解则直接返回None。至多k+1次SAT决策调用，不能把单次调用当常数成本。
工业solver返回任意模型还不够，需计入恢复first语义的调用；量子与经典都计入同一义务。

## 4. Q1的条件性不加速结论

设缩减域第一个满足赋值的零起始rank为j。直接枚举需j+1次谓词检查。

- 提议正好是第一个解：验证提议1次，证明此前j个都不满足需j次，总计j+1。
- 提议是更后面的满足解：验证1次，前缀扫描找到第一个解需j+1次，总计j+2。
- 提议无效或为空：经典回退至少完成原枚举；无解时要检查N个赋值。

在**相同谓词实现、相同缩减域、串行执行、不复用其他免费证据、量子附加成本非负**下，
经典工作包含基线所需全部检查，故 `T_Q1 >= T_enum`；量子附加成本为正则严格更慢。
把枚举作为可选保底策略的更强经典组合也不会被Q1击败。
不只是比较“检查次数单位”：Q1实际执行相同的必需谓词调用，额外检查不能抵消既有工作。

源示例直接枚举3次；提议first后修复3次，提议later后修复4次，量子部分还未计入。
该结论**只针对这一串行前缀枚举架构**；不推广到SAT证明、共享中间状态、量子回溯、
并行异步执行或所有量子算法。它也不证明该案例的正式quantumizable标签应改变。

## 5. 端到端成本账本与尚未识别的收益区域

按一次请求、串行调度，定义：

`T_hybrid = T_common + T_compile/R + T_prep + T_control + T_comm`

`           + Σ_a [T_init,a + r_a(T_oracle,a + T_diff,a) + T_measure,a]`

`           + T_decode + T_certificate + T_fallback`。

其中a遍历每次实际shot/attempt，r_a是该次迭代数；不要再额外乘一个shots数重复计费。
R是明确的编译复用次数，单次调用取1；多实例oracle变化可能使编译无法复用。
T_common含原输入检查/输出包装；T_prep含约束代入、oracle构造/序列化，不能免费。
通信包括提交及返回；是否计排队须对照部署需求预先确定。
T_certificate包括first/absence验证，T_fallback包括未解决请求的经典完成，不算成零。
若取期望，需从联合成功/噪声/重试分布推导，不假设独立重试即可免费纠错。
经典侧同样计预处理、求解、证书检查和输出；LLM开发/生成成本另列并声明如何摊销。

尚未代入硬件时，可写本oracle串行逻辑成本
`48τ_X + 54τ_CCX + τ_Z`，但τ不是物理原生门时间；需明确降解、路由、噪声和纠错模型。
逻辑qubit不能直接与设备标称物理qubit数比较。
[Beverland等 Fig.2、§III](https://arxiv.org/abs/2211.07629v1)说明跨层资源估计需要这些输入；
[Babbush等 §II](https://arxiv.org/abs/2011.04149v1)中的二次加速开销分析不能替代本案例校准。

| 条件 | 当前证据 | 收益判断 |
|---|---|---|
| inspect/retained或预处理即可解决 | 经典路径已有确定结果 | 不派发QPU |
| Q0，原始exact-first合同 | 源示例反例 | 不可作为替换 |
| Q1，§4全部假设 | 人工论证＋有限诊断 | 加速区域为空，无需伪造n* |
| Q2/Q3，可靠证明且资源适配，`T_hybrid < T_classical_competitive` | 证明器、强经典时间、硬件参数未齐 | 条件已列明，数值区域未知 |
| 具体用户QPU上实际任务收益 | [硬件profile](hardware-profile.json)为未知；未运行 | E5缺失，不作优势主张 |

因此这里只完成了**含明确否定条件和未知项的逐案例分析**，没有完成硬件参数化正收益预测。
Oracle逻辑计数支持局部E1/E2，不自动支持E3；Q1论证支持受限计划的成本判断，不是实测E4/E5。

## 6. 下一步：将行为义务转成有成本的证明计划

可优先落实的机制是：候选搜索不只生成量子算法，还生成
`原合同 → 需证明的义务 → oracle/算法/证明器/回退组合 → 完整成本 → 条件建议`。

在本例，给定已验证满足的y，first义务可分解为：对每个自由位i且y_i=True，证明
`F ∧ x_<i=y_<i ∧ x_i=False`不可满足。任意更小向量必在第一个不同位落入其中一项，
所以这些证明加F(y)足够；最多k个义务，不要求逐点枚举。其求解/证书验证成本仍可能指数级。
None则需要F本身的不可满足证据。可以复用增量SAT及证明检查技术；这里尚未实现证书链。

这给出具体推进点：**让first/absence义务改变方案搜索和成本估计，并保留强经典路线作为竞争者**。
已有方法能否通过普通工具组合做到同等效果，仍必须实测，不能因为本地实现了就宣称创新。
下一有限任务及对照/消融在[推进说明](../../../docs/quantum_advantage/PROGRESSION.md)。
