# MaxCut 规模与资源条件诊断

2026-09-28。用户要求检验研究效果，并指出四节点无收益不能回答规模增长后的收益问题。
本包据此考察 **规模、深度、物理资源、完整成本预算**，不重复四节点模型判断实验。

这是独立的 kernel 规模诊断：原 lit-001 wrapper 最多接受16节点，原正式案例不变。
超过16节点不计作原 API 的合法输入或正式 benchmark 结果。保留精确最优值和最小 mask
的输出目标，不把 QAOA 的近似解当精确结果。当前没有大规模 QAOA 成功率或便宜最优性证书，
因此计算的是必要时间预算，不能把预算为正当成已建立收益。

预先固定：n=8,16,24,32,48,64；三个固定种子；每图先构造环、三角形，再随机加边至2n条，
边权1..5。非二分图用于避免将原四环的简单经典结构误作困难工作负载。
这些合成图用于开发诊断，不代表独立程序、实际工作负载分布或未见测试集。

经典对照采用现有 SciPy 1.14.1/HiGHS 的整数 MaxCut 模型；首先最大化割权，随后逐位
从高到低固定最小mask。整体每实例求解预算3秒，限制/失败原样保存，不用超时阈值替代完成耗时。
同时核对 n<=8 与枚举输出一致。该对照强于直接Python枚举，但不宣称最强专用MaxCut solver。
求解器浮点最优状态不是形式证明；候选整数值与小实例枚举另行核对。

QDK 实际估算每个规模第一个种子的 QAOA 模板，深度 p=1,4,16，角度固定 pi/4，
100ns门/500ns测量、物理错误率1e-4、单电路估算错误预算1%，均为假设模型。
固定角度仅用于资源剖面，不作为已优化方案；不模拟大规模量子状态、不假定成功率。
单shot计数包含制备和测量；shots S 保持参数，不沿用小实例的64 shots。

对已完成的经典求解，输出必要条件
`S*t_shot + H < T_classical`，其中H包含构造、优化/编译摊销、控制通信、解码、
精确最优性及tie证明和回退。这里只推导可容纳这些未知项的预算；不把H设置为0作收益结论。
`T_classical/t_shot`仅是H>=0时shots的乐观上限。每个资源点只对应指定模型，不是全局阈值。

冻结配置、输入和代码hash在run/protocol.json；raw结果逐实例保存。无新LLM/QPU/安装/正式标签变化。
执行：`python -B run.py --output run`。输出目录必须不存在。

SciPy接口依据：[官方milp文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html)。
