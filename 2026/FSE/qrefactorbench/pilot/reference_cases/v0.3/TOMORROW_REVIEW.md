## 建议审查顺序：007 → 006 → 005 → 008，再回看原四组

1. **007 的功能/并列规则**：当前规则精确但不最小化存储或改动；可以选入零优先级项。
   是否保留？若改，在新公共输入版本中明确，不为以后量子输出事后改标准。
2. **006 的功能范围**：这是允许任意组件组合的费用下界评估，不承诺保留应用功能。
   是否过简？与 MaxCut 的代数相近，不能单靠新背景声称覆盖面显著扩大。
3. **005 的请求独立性**：每个请求都看同一库存快照，不能把两个“可行”理解为同时可行。
   是否符合你想评测的经典功能？
4. **008 的对照角色**：关注全量输出、顺序、别名；不是“循环很大就适合量子化”。
   是否允许 WHERE 提名后由 WHETHER 排除，仍须和最终指标一起明确。
5. **原四组**：仍需要功能/合同审查；新增数量不等于它们已通过。
6. **总体去留**：每组只记“保留 / 修改 / 淘汰 + 一句话理由”，再决定是否需要下一轮标注。

没有代填人类判断。未开展独立标注、裁决或新模型实验。

## 共同科学缺口

- 005/003：精确存在性与“没有抽到解”的区别；可逆 predicate、编码/算术成本、无解认证。
- 001/002/006/007：数学表示、硬可行性、解质量、精确/并列语义、完整报告分别审查。
  007 的容量约束罚项/slack 尚无已验证映射；没有假装它已有正确量子实现。
- 001 的近似 profile 已获允许，但容差未定；不自动推广到 002/006/007。
- 新例都缺少实际工作负载分布、硬件、编码成本与收益证据；**实用性可以继续 UNKNOWN**。
- 只有原 001/002 有已记录的 C2\|Q> 片段来源。其余是项目内合成/改编；没有新增论文来源。
- 函数名、目标函数和可见结构可能让定位很容易；没有证据证明第二层更难。
- 两层配对和已有 pilot 父来源要成组；不能拆成独立训练/测试观测。相同二次目标形式
  或子集枚举结构还可能产生跨组泄漏，最终划分须审查。
- 新代码许可仍 `NOASSERTION`；没有替你决定发布权利或批准冻结。
